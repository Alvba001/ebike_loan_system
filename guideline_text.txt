Introduction
• In most universities all over the world, undergraduate students in
their final year are expected to complete a research project as part
of their requirements for graduation.
• Students going through  Software Engineering or related program
are normally required to execute software projects which involve
going through the complete system development cycle from
beginning to end.
• In spite of the fact that such students take courses on research
methodology and Software Engineering during their programs,
many of them, by the time they start these projects, have little or
no ideas on how to systematically carry out such software
projects.
• This presentation is to guide such students in how to carry out
Software Engineering projects from beginning to end and how to
fully prepare the documentation for these projects.

General Formatting
• The writing should be in Times New Roman Font Type. 12points,
Line Spacing 1.5
• Chapters Heading should be in Centralized Alignment
• Sub-Sections should be in Left Alignment
• Inside each Subsection, the writing Should be Justified aligned.
• APA reference style should be used.
• Page Numbering should be in center of a page.
• Each Chapter should start on a new page.
• All abbreviations must be written completely the first time they
are used with parenthesis around the abbreviation.
• All figures and tables must be numbered according to the chapter
and referenced inside the chapter.
• For example the first figure in chapter 3 should be labelled Figure 3.1, the
fourth table in chapter 4 should be Table 4.4.
• Tables are labelled at the Top, Figures are labelled at the bottom.
• Both Tables and Figures and their labels are center aligned.

• Acknowledgements: A section where the author(s) can thank
individuals, organizations, or institutions that helped in the
completion of the project.
• Table of Contents: Lists the main sections and subsections of
the project, along with their page numbers, providing an
organized outline of the document.

figures, tables, or illustrations, this list helps readers quickly
locate these items.

Background(one sentence),a clear statement of the aim,
methodology(a sentence on each chapter)and conclusions.
• Written in present tense.

Problem Statement
• Problem Statement is a clear description of the problem that
the project is addressing.
• The problem statement should generally have two (2)
paragraphs. The first paragraph should state the problem that
is the reason for the project. The second paragraph should
describe the proposed solution.
• Example: Problem Statement for a Student Record System
The current student record management system at  XYZ university
involves extensive paperwork for managing student enrolment,
academic records, and attendance. This process is error-prone,
time-consuming, and prone to data loss or mismanagement.
Additionally, generating reports and retrieving student information
requires considerable effort and often results in delays.
Hence the need for an automated system that solves the above
mentioned problems

Aim and Objectives
• The aim should normally be written using an infinitive verb,
something like: The aim of this project is to develop, to generate,
to map, to build, to investigate, to explore
• Objectives are often presented as a formatted list and they
should clearly make visible the sequence of big steps in the
project with each step having a definable outcome.
Example
The Aim of this project is to develop an event hall booking
system that simplifies the process of reserving and managing
event spaces. The Objectives are:
i. To design and implement functionalities for searching, viewing,
and reserving event halls.
ii. To design and implement set up notifications  feature to
confirm bookings and remind users of upcoming events.
iii.  To design and implement an admin panel for managing
bookings and updating hall information.

Significance of Study
• Significance of the Study: Here students are to explain the
importance and potential impact of the research.
• It should outlines how the project contributes to existing
knowledge, solves a problem, or benefits specific groups.
• Example: Significance of Study for a Student Record System
This project aims to improve how educational institutions manage
student records by developing an efficient, automated system. The
system will reduce manual errors, enhance data security, and
allow easy access to student information, benefiting both
administrators and students. It will also save time and resources,
contributing to a smoother administrative process and better
decision-making based on accurate data. This study can serve as a
foundation for future improvements in student record management
systems.

Scope
• Scope: Here students are to define the boundaries and specific
aspects that their study will cover.
• It should outlines what the project will include, what it will not
address, and any limitations or constraints.
• Example: Scope for a Student Record System
This project will develop a Student Record System that automates
student data management. The system will include:
1.Features: Automated data entry, secure login, real-time updates,
and simple interfaces for users.
2.Users: Administrative staff and students.
The project will not include mobile app development or integration with
external systems. It will focus only on creating a web-based system for
managing student records.

Summary
• Summary: Here students are to to reinforce the chapter’s content
and ensure that readers understand the essential takeaways.
• Example : Chapter 1 summary for a topic Student Record System
This Chapter introduced the development of a Student Record System
designed to enhance the management of student data in educational
institutions. The chapter outlined the challenges associated with
traditional record-keeping methods, including inefficiencies and
security concerns. Key points discussed include the need for improved
data accuracy, automated processes, and secure access controls. The
chapter also highlighted the objectives of the project, which include
creating a system with automated data entry, real-time updates, and
user-friendly interfaces for administrative staff and students. The
chapter set the stage for the subsequent sections by establishing the
context and importance of the project, paving the way for a detailed
exploration of the system’s design and implementation in the following
chapters.

Use Case  Name : Login                                                         Priority : High
Actor: Shopper
Description: This use case documents the procedure for logging into the library management
system.
Trigger : External
Preconditions : The system database is up-to-date and on-line
Normal Course:
1) The system requests that the actor enters his/her user id and password.
2) The actors enters user id and password.
3) The system validates the user id and password (Alternative course).
4) The user is logged into the system
5) The use case ends.
Alternative course:
4b. The user id or password is invalid
1) The System ask the user for a valid password
2) The User enters another wrong password
3) The system blocks the user
4) The Use Case ends
Post Conditions: The login record is saved.
Exceptions:
1) The System displays  “Invalid User name or password”
2) The System displays  “Re-enter a valid password”
3) The system display “You have been blocked contact admin to resolve login issue”
